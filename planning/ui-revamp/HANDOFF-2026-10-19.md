# Handoff, 19 Oct 2026: native microphone policy and direct reviewed insert (incomplete checkpoint)

This covers branch `claude/compassionate-hawking-m9x36g`. It is a work-in-progress checkpoint on top of `31dcb60`, which holds the island shell and the contract in `ISLAND-INTEGRATION.md`. Nothing here was run on Windows.

## What this checkpoint adds (typecheck passes)

### Native microphone policy

- **The setting:** `settings.voiceInput` (default `false`) in `electron/services/validation.ts` and `src/shared/contracts.ts` (optional field).
- **Turning it on from the hub:** `saveSettings({voiceInput: true})` lists `MIC_PERMISSION_CHANGE` among the changes that need the hub's trusted confirmation. Turning it off needs none. An import keeps the current value.
- **Enforcement:** `electron/main.ts` runs `voiceAllowed()`, and `mediaPermissionAllowed({..., voiceInput})` in `electron/companionCore.ts` refuses all audio while the setting is off, in both the request handler and the check handler.
- **Turning it on from the companion:** the new island-only method `companionSetVoiceInput(boolean)` uses the island's own trusted confirmation (`CompanionVoice.setInput`). `companionVoiceStatus` now includes `inputAllowed`.
- **Change notices:** `CompanionVoice.onPolicy`. Every change (from the hub, the island or `saveSettings`) pushes `{type: 'voice-policy', allowed}` to the island.

### Renderer consent

- **`src/voice/consent.ts`:** `nativeMicConsent({initial, set})`. Browser storage is no longer the authority.
- **`VoiceSession`:** `setConsent(on)` is now async and asks the main process when the consent is native. `syncConsent(allowed)` follows outside changes and cancels a recording when the policy turns off.
- **Hub Assistant (`src/components/Assistant.tsx`):** uses the native consent built from `settings.voiceInput` and `api.saveSettings`.

### Direct reviewed insert (no Claude call)

- **Island-only method:** `companionInsertText(text)` (1 to 2000 characters), exposed as `window.companion.insertText`. It runs as its own request (so Stop or `companionCancel` aborts it), bound to the remembered window, and only while that window is still attached and the bubble is open.
- **Backend:** `CompanionService.insertText` runs the existing `type_into_app` tool directly through `runToolDirect` in `agent.ts`, with the same validation, preview, trusted confirmation (closed as Cancel on Stop), window re-check, partial-input reporting and "typed, not read back" receipt. The final event is an `answer` with `steps: 0`, meaning no request went to Claude.
- **`typeIntoTarget`** now re-checks `current()` after Continue. A Stop, a removed window or a closed bubble while the dialog was open means nothing is typed. This also affects the Claude typing path.
