## Direction recommended for the implementation brief

1. Start with usability: five or six understandable work areas, one visible primary action per view, contextual details instead of a wall of cards/settings, plain labels and actionable empty/error states.
2. Design one original identity: carefully spaced typography, calm neutral surfaces, one accent, a purposeful orb, consistent icons/materials. Choose a distinctive visual direction after side-by-side screenshot review.
3. Make the orb useful: idle/listening/transcribing/working/speaking/error are distinct real states with visible text and an accessible stop action. Never animate fake activity or expose hidden reasoning.
4. Avatar studio: curated original/local presets with consistent art direction, a useful large preview, clear customization controls and honest unsupported states. Avoid one crude character standing in for the whole feature.
5. Build a reusable shell, tokens and components before migrating individual screens. Review representative dense, empty, error and voice-active views at real Windows sizes.
6. Verify keyboard flow, contrast, focus, reduced motion and low-performance fallback; use user-facing task walkthroughs alongside tests. Marketing visual polish does not establish that the installed application's features work.
